# envs 目录说明

本目录保存强化学习环境相关代码，是项目中最重要的仿真与接口层。

## 文件职责

- `base_env.py`：后端无关环境基类，负责 34 维观测构造、动作缩放、通用终止判断和课程策略接口。
- `drone_landing_env.py`：PyBullet 后端实现，用于 Python 预训练阶段的轻量仿真和可视化。
- `square_flight_test.py`：独立 PyBullet 正方形航线演示，用于验证基础运动学控制，不参与 Gym 训练主流程。

## 子目录职责

- `dynamics/`：无人机运动学模型、速度指令低通滤波和 PyBullet 预训练扰动。
- `landing_platform/`：降落平台运动轨迹生成。

## 分离边界

`BaseDroneLandingEnv` 中的观测构造和动作缩放是未来迁移最值得复用的部分。`DroneLandingEnv` 只代表当前 PyBullet 仿真后端，迁移到 ROS/Gazebo 时可以替换为新的后端类。

课程相关指标、成功判断和奖励由活动策略定义。迁移到 ROS/Gazebo 后端时，后端只需提供等价状态，策略即可独立决定如何使用这些状态。

## 迁移提示

未来 ROS1 + MAVROS + PX4 / Gazebo 工程应提供等价的状态来源：

- 无人机位置、速度、姿态和 yaw rate。
- 平台位置、速度、姿态、角速度和检测质量。
- 上一时刻动作和实际可用速度能力。
- 无人机局部高度/对地高度/海拔高度抽象量，当前 PyBullet 中由 `drone_z - platform_z` 近似。

然后复用同一套 34 维观测构造规则和动作缩放规则，以保证训练输入和工程部署输入一致。

注意：当前 PyBullet 后端中的无人机 `velocity` 已经是扰动和速度跟踪误差后的实际速度。迁移到 ROS/Gazebo/PX4 后，应使用飞控/里程计估计出的实际速度填充同一字段，而不是把 RL 输出的速度指令当作观测速度。
